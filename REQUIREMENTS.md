# SWOT Analyzer - Полное техническое задание

## 1. Технический стек и архитектура

### Основные технологии
- **React**: 18.2+
- **TypeScript**: 5.3+
- **UI Framework**: React + CSS Modules
- **State Management**: Zustand
- **Графики**: Recharts
- **Виртуализация**: @tanstack/react-virtual
- **Валидация**: Zod
- **Хранение данных**: JSON (1 проект = 1 файл)
  - Путь: `~/SWOTProjects/` (Linux/Mac)
  - Путь: `%USERPROFILE%\SWOTProjects\` (Windows)
- **Упаковка/дистрибуция**:
  - Windows: MSIX (предпочтительно) или NSIS (.exe)
  - Linux: AppImage или DEB
- **Стиль/темы**: CSS Variables + CSS Modules - светлая тема основная, тёмная опционально
- **Сборщик**: Vite
- **Десктопная платформа**: Electron
- **Управление зависимостями**: npm/yarn

### Архитектурный паттерн: React + Zustand Store

```
View (React Components) → Store (Zustand) → Services (Business Logic) → Types (TypeScript) → Storage (Electron API)
```

## 3. Валидация

### 3.1. Правила валидации Factor

- `type` (S/W/O/T) - **обязателен**
- `text` - **обязателен**, непустая строка
- `category` - **обязателен**, непустая строка
- `significance` - **обязателен**, диапазон 1..5
- `impact` - **обязателен**, диапазон 1..5
- `probability` - **обязательна для O/T**, диапазон 1..5
  - Для S/W факторов `probability` не требуется (может быть None)

### 3.2. Визуальная индикация ошибок

- **В списке факторов**: Ошибочные строки подсвечиваются красным фоном через QSS
- **В экране расчёта**: Отображается список ошибок с описанием и способами исправления
- **Валидация в реальном времени**: При изменении полей фактора проверка выполняется через signals/slots

## 4. Производительность

### 4.1. Требования к производительности

- Приложение должно корректно работать при **~200 факторах** без заметных лагов
- **Виртуализация списка**: QTableView использует встроенную виртуализацию (QAbstractItemView)
  - Использовать QStandardItemModel или QAbstractTableModel
  - Избегать создания QWidget для каждой строки
- **Мемоизация расчётов**: 
  - Использовать `functools.lru_cache` для дорогих вычислений
  - Кэшировать агрегаты (суммы по квадрантам, топ факторы)
  - Инвалидация кэша при изменении факторов

### 4.2. Оптимизация пересчёта

- Пересчёт агрегатов только при изменении факторов
- Использовать Qt signals для уведомления об изменениях
- Ленивая загрузка данных в таблицу

## 5. Требования к UI (современный desktop-вид)

### 5.1. Единая дизайн-система

- **Отступы**: Единые значения (например, 8px, 16px, 24px)
- **Размеры контролов**: 
  - Кнопки: минимальная высота 32px
  - Поля ввода: высота 32px
  - Таблицы: минимальная высота строки 40px
- **Скругления**: Единое значение (например, 4px или 6px)
- **Типографика**: 
  - Заголовки: 18-24px, полужирный
  - Основной текст: 14px
  - Вспомогательный: 12px
- **Состояния контролов**:
  - `hover` - изменение цвета фона/границы
  - `pressed` - более тёмный оттенок
  - `disabled` - серый цвет, пониженная непрозрачность
  - Особое внимание к Windows (корректная работа hover/pressed)

### 5.2. Визуальная структура окна

```
┌─────────────────────────────────────────┐
│  Верхняя панель (навигация/действия)    │
├─────────────────────────────────────────┤
│                                         │
│      Центральная рабочая область       │
│      (QStackedWidget с этапами)        │
│                                         │
├─────────────────────────────────────────┤
│  Нижняя панель (Назад | Далее)         │

```

- **Верхняя панель**: Название проекта, кнопка сохранения, меню настроек
- **Центральная область**: Контент текущего этапа (0-5)
- **Нижняя панель**: Кнопки навигации "Назад" и "Далее" (disabled на первом/последнем этапе)

### 5.3. Сворачиваемые секции

- Использовать `QGroupBox` с `setCheckable(True)` для простых accordion
- Или кастомный виджет для анимированных accordion (QPropertyAnimation)
- Вместо перегруженных страниц использовать сворачиваемые секции

### 5.4. Темы

- **Светлая тема**: Основная, по умолчанию
- **Тёмная тема**: Опциональная, переключение через меню/настройки
- Сохранение выбора темы в конфигурации

## 6. Архитектурные требования

### 6.1. Слои (адаптация под PySide6)

- **UI Layer (views/)**: 
  - QWidget/QMainWindow наследники
  - Только обработка пользовательского ввода
  - Подписка на signals ViewModel
  - Обновление UI через slots

- **ViewModel Layer (viewmodels/)**:
  - Аналог Store (zustand/redux) в React
  - Использует Qt properties (Q_PROPERTY) для observable state
  - Signals для уведомления об изменениях
  - Преобразование данных для UI
  - Управление состоянием представления

- **Service Layer (services/)**:
  - `calculation_service.py` - расчёты (score, агрегаты)
  - `validation_service.py` - валидация данных
  - `storage_service.py` - работа с файлами (обёртка над repository)
  - `strategy_service.py` - генерация стратегий SO/WO/ST/WT

- **Model Layer (models/)**:
  - Pydantic модели для валидации
  - Сериализация/десериализация JSON

- **Repository Layer (repositories/)**:
  - Работа с файловой системой
  - JSON загрузка/сохранение
  - Миграции схемы

### 6.2. Изоляция логики

- **UI не содержит**:
  - Расчётных формул
  - Логики сохранения
  - Валидации данных

- **Все вычисления и валидация** находятся в:
  - Services (бизнес-логика)
  - ViewModels (преобразование для UI)
  - Models (валидация структуры данных)

### 6.3. Событийная модель Qt

- **View → ViewModel**: Пользовательские действия через signals
- **ViewModel → View**: Обновление UI через slots, подключённые к signals ViewModel
- **Service → ViewModel**: Уведомления об изменениях через signals
- **Repository → Service**: Уведомления об успешной/неуспешной загрузке/сохранении

## 10. Особенности реализации

### 10.1. Многоэтапный интерфейс

- QStackedWidget в главном окне для переключения между этапами 0-5
- Каждый этап = отдельный QWidget страница
- Навигация через кнопки "Назад"/"Далее" в нижней панели

### 10.2. Таблицы и фильтрация

- QTableView + QStandardItemModel для таблицы факторов
- QSortFilterProxyModel для сортировки по score и фильтрации
- Фильтры: QComboBox (тип S/W/O/T, категория), QLineEdit (поиск по тексту)
- Подсветка ошибок через кастомный делегат и QSS стили

### 10.3. Визуализация

- Qt Charts (QBarChart) для столбчатого графика по категориям
- Кастомный QWidget для SWOT-матрицы 2×2 (4 квадранта)
- Топ факторов через QListView или QTableWidget

### 10.4. Расчёты

- Service Layer для бизнес-логики:
  - Расчёт `score` для факторов:
    - S/W: `score = significance × impact`
    - O/T: `score = significance × impact × probability`
  - Суммы по квадрантам (ΣS, ΣW, ΣO, ΣT)
  - Сводка по категориям (суммы score по категориям)
  - Генерация стратегий SO/WO/ST/WT на основе топ-N факторов

### 10.5. Хранение проектов

- Каждый проект = отдельный JSON файл
- Имя файла: `{project_id}.json` (UUID или timestamp-based)
- Путь: 
  - Linux/Mac: `~/SWOTProjects/`
  - Windows: `%USERPROFILE%\SWOTProjects\`
- Автоматическое создание директории при первом запуске
- Валидация JSON при загрузке через Pydantic
- Поддержка миграций схемы через поле `schema_version` в JSON
- Обработка ошибок при повреждённом JSON
